# Development setup

Status: the workspace is a Git repository. No Lens Studio project, CLAD connection, or working Lens has been verified yet.

## Required order

1. Install/open Lens Studio. The hackathon recommends 5.23.2 if newer versions block CLAD sign-in; verify the current organizer advice before installing.
2. Create a **SPECS > Base Template** project named **Threadback** and save the actual project files at the repository root. If Lens Studio creates a nested folder, move the project contents into this repository only after checking paths and avoiding overwrites. Do not fabricate an `.esproj` or `.mcp.json` file.
3. Keep the project open in Lens Studio and start the coding agent from the folder containing the `.esproj` file.
4. Follow [Snap's CLAD setup for Codex](https://developers.specs.com/docs/clad/setup/setup-ai/codex-setup). Confirm the real Lens Studio MCP connection and CLAD tools are available. Treat MCP connection settings as local configuration and do not publish credentials.
5. In the project folder, install the official planning skill pack:

   ```sh
   npx skills add challengepost/learn-specs --all -y
   ```

6. Run `plan-lens`. Use the agreed scope and demo notes as conversation context, answer remaining design questions, and commit the resulting `devpost/design-brief.md` and other generated planning documents.
7. Build using CLAD and the Lens Studio MCP from that brief. Implement one complete feature at a time, inspect the real preview, and record validation evidence.

Node.js and Git are available in the current workspace environment. Lens Studio installation and the official planning skill have not been completed as part of repository scaffolding.

## Git layout

The repository root should become the actual Lens Studio project folder. Keep Lens Studio assets, scene files, and scripts in the locations created by the template/tools rather than introducing an unrelated web app structure.

Tracked support files:

- `docs/`: scope, roadmap, setup, and demo notes.
- `devpost/`: documents generated by the official planning skill, once run.
- `.github/`: issue and pull request templates.

Do not commit local credentials, signing keys, machine-specific MCP configuration, dependency caches, or exported demo recordings. Review newly generated Lens Studio files before adding them; preserve source assets and necessary metadata.
